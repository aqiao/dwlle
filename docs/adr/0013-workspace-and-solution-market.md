# 0013 我的工作空间与方案市场分离

状态：已接受（术语部分被 0014、0015 取代，导航以现行声明为准）
日期：2026-11-03

> 现行架构声明（2026-11-08）：现行可执行约束单独列于下节。原四项主导航及 Project/Pipeline 术语仅保留作历史记录，不得直接实施。当前主导航为“日常工作、数据管理、方案市场”，开发者集成归入 Workspace 设置。

## 现行有效约束

1. 主导航固定为“日常工作、数据管理、方案市场”。
2. 日常工作只包含当前企业自有或已安装的 Scenario/Workflow 及运行状态，不混入社区共享模板。
3. 数据管理提供统一 DataAsset 入口，DataSource、File、Dataset 是资产类型，可按类型提供不同视图。
4. 方案市场只包含官方或社区只读的 Solution/Scenario/Workflow 模板及安装管理，不显示企业实时运行状态。
5. 模板与企业实例严格分离。实例可以本地修改和运行，升级通过版本差异比较和人工确认完成，不覆盖本地修改。
6. API/MCP、服务账号、Scope 和工具清单归入 Workspace 设置，不再设置独立的“开放集成”主导航。
7. 个人账户与界面偏好归入个人设置。
8. 真实市场、安装、升级、支付和共享发布的交付范围由阶段计划决定。

## 背景

ADR-0011 引入 Solution、Scenario 和 Pipeline 三层复用后，原型把解决方案、业务场景和 Pipeline 放在同一工作空间。企业自己的运行实例与其他用户共享的模板具有不同目标和生命周期，混在一个列表中会模糊当前状态、修改权限和对象来源。

“资源中心”容易被理解为企业内部资源，“数据集市”是 Data Mart 的专门术语，均不适合作为外部方案与模板市场的名称。

## 历史决策（不得直接实施）

1. 导航曾分为我的工作空间、数据管理、方案市场和开放集成，其中开放集成作为独立导航提供 API 与 MCP。
2. 我的工作空间只包含当前企业的 Scenario/Pipeline 实例及运行信息。
3. 方案市场只包含共享模板及安装管理。
4. 安装模板时在指定 Project/Environment 创建独立企业实例，升级不覆盖本地修改。
5. 统一命名为“方案市场”，共享内容使用“模板”与实例区分。
6. 原实施边界为不在 2026 年 11 月 Alpha 增加真实市场、安装、升级、支付或共享发布能力。

## 历史理由与后果（仅作历史记录）

- 日常办公关注企业任务与状态，发现模板是按需行为，分开更合理。
- 模板与实例分离可防止用户误改共享内容，并明确本地修改与上游升级关系。
- 场景和 Workflow 模板需要独立入口，不能只依赖共享筛选。
- 已安装实例需要保留来源模板版本、本地版本和升级关系。
- 后续市场实现必须管理安装记录和版本差异，不能只提供下载。
