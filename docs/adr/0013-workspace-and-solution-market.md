# 0013 我的工作空间与方案市场分离

状态：已接受
日期：2026-11-03

## 背景

ADR-0011 引入 Solution、Scenario 和 Pipeline 三层复用后，原型把解决方案、业务场景和 Pipeline 放在同一工作空间。企业自己的运行实例与其他用户共享的模板具有不同目标和生命周期：前者用于日常运行和修改，后者用于发现、安装和升级。混在同一列表会模糊当前状态、修改权限和对象来源。

“资源中心”容易被理解为企业内部资源，“数据集市”又是 Data Mart 的专业术语，均不适合作为外部方案与模板市场的名称。

## 决策

1. **导航分为我的工作空间、数据管理、方案市场和开放集成。**
   - 我的工作空间：工作台、业务场景、Pipeline、运行中心、SQL。
   - 数据管理：数据资产、数据源。
   - 方案市场：解决方案、场景模板、Pipeline 模板、已安装与更新。
   - 开放集成：API 与 MCP。

2. **我的工作空间只包含当前企业的实例。** 包括企业自行创建或从方案市场安装后生成的 Scenario/Pipeline，以及其运行状态、SLA、草稿、版本、告警、成本和权限。

3. **方案市场只包含共享模板及安装管理。** 官方或其他用户的 Solution/Scenario/Pipeline 模板默认只读，提供版本、作者、兼容性、权限和资源需求，不显示企业实时运行状态。

4. **模板与实例严格分离。** 安装模板时在指定 Project/Environment 创建独立企业实例。实例可以本地修改和运行；共享模板不能被购买者直接修改。升级通过上游版本差异比较和人工确认完成，不覆盖本地修改。

5. **统一命名为“方案市场”。** 页面副标题为“发现、安装和升级可复用的数据解决方案与业务模板”。场景和 Pipeline 的共享内容明确使用“模板”，避免与实例混淆。

6. **保持当前实施边界。** 本次只调整信息架构、文档和原型，不在 11 月 Alpha 增加真实市场、安装、升级、支付或共享发布能力。

## 理由

- 日常办公关注企业任务与状态，发现模板是按需行为，分开可减少认知负担。
- 模板与实例分离可防止用户误改共享内容，并明确本地修改与上游升级关系。
- “方案市场”比“资源中心”更明确外部发现语义，也避免 Data Mart 的歧义。

## 后果（含代价与风险）

- 需要为场景和 Pipeline 模板提供独立入口，而不能只依赖共享筛选。
- 已安装实例需要保留来源模板版本、本地版本和升级关系。
- 后续市场实现必须同时管理安装记录和版本差异，不能只提供下载。
