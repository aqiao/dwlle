# 0010 客户可见界面全部由 dwlle 自研

状态：已接受
日期：2026-11-02

## 背景

ADR-0008 为缩短 MVP 周期，将 DAG 画布、复杂依赖、补数据和告警等操作留在 DolphinScheduler 原生界面。新的产品要求是所有客户可见界面均由 dwlle 提供，以保证统一交互、权限、审计、AI 运维和 UI 定制能力。

DolphinScheduler 的 UI 与调度引擎可以分离。自研 UI 不意味着重新实现调度能力，也不意味着首版必须复刻 DS 的全部功能。

## 决策

1. **客户可见界面 100% 由 dwlle-web 提供。** 包括项目、数据源、Pipeline DAG、SQL IDE、数据资产、质量、运行中心、日志、告警、AI 诊断和管理页面。
2. **DolphinScheduler 只作为后台执行引擎。** 不使用 iframe，不向客户提供 DS 深链接，不要求客户登录 DS 完成任何产品流程。
3. **DS 原生 UI 仅限内部管理员紧急排障。** 使用独立管理账号和受控访问；普通用户无访问权限，紧急修改必须记录并回到 dwlle 重新发布一致版本。
4. **所有 DS API 调用集中在 dwlle-api 的 DS client。** 前端不直接访问 DS，DS Token 不下发到浏览器；dwlle 负责用户权限与审计。
5. **dwlle Pipeline 是定义事实来源。** 草稿经校验和发布后形成不可变版本，由编译器单向生成 DS 工作流；运行实例始终关联已发布版本，DS 定义不反向同步。
6. **首版自研简单 DAG。** 支持串行、并行分支、汇合、节点配置、校验、草稿、版本、发布和回滚；首版节点限定为 SeaTunnel、Trino SQL、质量检查和通知等 P0 类型。
7. **节点配置由组件元数据驱动。** 后端提供组件参数 Schema、输入输出约束和引擎要求，前端据此渲染表单，避免为每种节点重复建设编辑器。
8. **复杂能力按需求后续实现。** 跨项目依赖、子工作流、补数据、复杂日历、Worker 分组和 DS 全量任务类型不属于 2026 年 11 月 Alpha。

## 理由

- 自研 UI 是统一体验、AI 辅助和后续组件市场的必要基础。
- 保持 DS 在后台可复用成熟调度能力，同时避免两套权限、审计和定义来源。
- 限制首版 DAG 和节点范围，可以在月底交付完整工作流，而不是把精力消耗在复刻 DS 全部界面上。
- 元数据驱动表单有利于增加组件和版本，不需要不断修改前端主体。

## 后果（含代价与风险）

- 团队需要承担 DAG 编辑、运行中心、日志和部分调度运维界面的开发与测试。
- 首版不再以“跳转到 DS”作为高级功能兜底；超出 P0 的调度能力必须延后或另立任务。
- 自有 Pipeline 编译器必须处理版本映射、状态一致性和 DS API 升级。
- DS 管理员的紧急修改可能造成定义漂移，必须尽量禁止并建立恢复流程。
- 本 ADR 取代 ADR-0008；其中 dwlle-web 主路径和 DS client 集中封装原则被保留并强化。
