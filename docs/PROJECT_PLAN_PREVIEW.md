# dwlle Preview 开发计划

版本：v1.0（2026-11-08） · 状态：撰写中（待批准）
计划窗口：2027-01-01～2027-01-31
关联文档：[架构设计](ARCHITECTURE.md)、ADR-0001～0017（含取代关系与各文件现行声明）
上一阶段：[Beta 开发计划](PROJECT_PLAN_BETA.md) · 下一阶段：GA Go/No-Go 评审

## 1. 阶段目标

面向受邀用户开展试运行，验证真实使用场景、部署运维流程和反馈处理机制，形成 GA Go/No-Go 决策依据。

Preview 以稳定性、反馈和发布准备为主，不默认引入新执行引擎、新数据格式或新核心领域对象。网站与社区建设不得影响产品缺陷修复和试运行验收。

## 2. 前置条件

- Beta P0 验收完成，或未验收项已明确记录并经评审不阻塞受邀试运行。
- 标准数据链路、OpenMetadata 血缘、质量阻断、权限隔离和恢复流程可重复演示。
- 已提供部署、升级、备份恢复、故障处理和已知限制文档。
- 已确定受邀用户、支持窗口、反馈渠道和问题分级负责人。

## 3. 工作范围

### 3.1 P0：Preview 必须完成

| 领域 | 包含范围 | 完成定义 |
|---|---|---|
| 邀请制试运行 | 受邀 Tenant、Workspace、Environment 和支持流程 | 用户可按文档完成核心场景，不开放公网自助注册 |
| 真实场景验证 | 至少一条用户真实或等效数据链路 | 接入、转换、质量、血缘和排障结果可复现 |
| 反馈管理 | 缺陷、体验问题和能力请求分级记录 | 有负责人、处理状态、版本和验证结果 |
| 稳定性 | 关键组件运行观察、失败恢复和资源限制 | 无未处理的阻断级问题，故障可按手册定位 |
| 安全与隔离 | 越权、密钥、日志、原生管理入口和数据保留复核 | 无高危安全问题，OpenMetadata 原生 UI 仍不面向客户 |
| 升级与恢复 | Alpha/Beta 到 Preview 候选升级及恢复演练 | 升级步骤可重复，失败可回滚，权威血缘不丢失 |
| 成本与容量 | 真实试运行资源、查询和存储指标 | 成本基线更新，容量限制和超配额行为可解释 |
| 文档与培训 | 用户指南、部署运维、演示和已知限制 | 新用户可按文档完成 onboarding |
| 网站与社区 | 官方网站基础内容、文档入口和反馈渠道 | 内容与安全审查通过，不发布未经验证的能力承诺 |
| GA 评审 | 发布候选、回滚制品、未验收项和 Go/No-Go 材料 | 评审结论和附带条件明确 |

### 3.2 可纳入的反馈修复

- 不改变核心架构的可用性、性能、错误提示和文档改进。
- 已支持连接器的兼容缺陷和资源限制调整。
- DataAsset、Workflow、质量或血缘同步中的可复现缺陷。
- 经架构评审确认不改变权威模型的小型增强。

### 3.3 不默认纳入

- 新执行引擎、实时 CDC 或新默认数据格式。
- 第二权威血缘存储或绕过 OpenMetadata 的同步路径。
- 公开/付费市场、自动分成和第三方任意代码上传。
- 生产级跨账号、多区域和高可用架构的临时扩张。
- 自动修复、自动扩容和未经审批的 Agent 写操作。

## 4. 阶段安排

| 时间 | 目标 | 出口条件 |
|---|---|---|
| 01-01～01-07 | 发布 Preview 候选并完成受邀用户 onboarding | 首批用户可运行核心场景，反馈渠道可用 |
| 01-08～01-14 | 收集真实反馈并处理阻断问题 | 缺陷分级准确，阻断问题有修复和回归结果 |
| 01-15～01-21 | 完成升级、恢复、安全、成本和文档复核 | 发布准备检查项有证据，未验收项明确 |
| 01-22～01-28 | 回归验证和 GA 候选冻结 | 核心场景回归通过，只处理 GA 阻断问题 |
| 01-29～01-31 | GA Go/No-Go 评审 | 形成上线、延期或带条件上线决定 |

## 5. 反馈优先级

| 级别 | 定义 | 处理原则 |
|---|---|---|
| P0 | 数据丢失、跨租户越权、密钥泄露、核心链路不可用 | 立即停止相关发布，优先修复并回归 |
| P1 | 权威血缘错误、质量未阻断、升级不可回滚、严重性能问题 | GA 前必须修复或明确限制使用范围 |
| P2 | 非阻断功能缺陷、明显体验问题 | 纳入修复计划并记录版本 |
| P3 | 新数据源、新引擎、新治理功能等能力请求 | 进入后续路线图，不挤占 Preview 稳定性工作 |

## 6. Preview 验收

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 受邀用户按文档完成 onboarding | 无需研发代替操作即可完成基础配置 |
| 2 | 运行真实或等效数据链路 | 接入、转换、质量、血缘和日志结果正确 |
| 3 | 注入任务失败和元数据组件故障 | 可定位并恢复，AI 不执行写操作 |
| 4 | 执行版本升级和回滚 | Workflow、DataAsset、Polaris 和 OpenMetadata 数据保持一致 |
| 5 | 核对 OpenMetadata 血缘与 dwlle 缓存 | OpenMetadata 仍是唯一权威，缓存可重建 |
| 6 | 检查跨租户、跨 Environment 和管理入口权限 | 越权被拒绝，测试/生产密钥不混用 |
| 7 | 通过 REST/MCP 执行只读血缘与运行查询并检查审计 | 权限取交集且越权被拒绝，审计保留 actor/agent/scopes，不暴露 OpenMetadata 管理凭证 |
| 8 | 完成成本与容量复核 | 资源指标和估算成本可解释，限制行为符合文档 |
| 9 | 检查网站与社区内容 | 无未验证能力、生产 SLA 或低成本承诺 |
| 10 | 汇总未验收项和发布材料 | Go/No-Go 证据完整，责任和附带条件明确 |

## 7. GA Go/No-Go 条件

GA 默认要求：

- Preview P0 验收完成，无未处理的 P0/P1 问题。
- 核心链路、升级回滚、权限隔离和恢复演练通过。
- OpenMetadata 血缘权威模型无已知双写或同步覆盖问题。
- 文档、支持、成本、已知限制和回滚制品齐备。
- 对仍未达到生产要求的能力明确降级、限制或延期，不以 Preview 试运行替代生产验收。

GA 如需承诺生产 SLA、高可用、跨账号或多区域，必须另行补充架构设计、资源和实测证据，不能由本计划默认推导。

## 8. 阶段交付物

- Preview 候选版本、试运行记录和反馈处理清单。
- 真实场景验证、升级回滚、恢复、安全和成本报告。
- 用户指南、部署运维手册、培训材料和已知限制。
- 官方网站基础内容、文档入口和社区反馈渠道。
- GA Go/No-Go 评审材料、未验收项和后续路线图建议。
