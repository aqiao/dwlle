# Alpha 周计划第三轮只读审查报告

## 摘要结论

在限定审查范围内，未发现可由 `docs/PROJECT_PLAN_ALPHA.md`、`docs/ARCHITECTURE.md` 与 `docs/ROADMAP.md` 的文本直接证实，且会阻断 Alpha 任务执行、进度追踪或 A5 阶段验收的矛盾或遗漏。

本轮重点复核的两项已经处理清楚：

1. **第 5.1 节历史基线**：所有仍被 Alpha P0 或后续任务引用的历史基线均在表中具备 Owner/交叉审核角色、A5 前复核目标日、统一状态和具体任务文档证据。原先的“已完成（历史）”语义已经由“已实现待验收”和“已验收”替代或映射；正文明确说明历史交付记录不等于 Alpha P0 验收，且“已实现待验收”不能直接作为第 5.7 节已验收前置。已被取代的 T001～T003 标为“不适用”，不再构成当前 P0 基线，故其无 Owner/日期不构成遗漏。
2. **T0069 前置、候选 SHA 与 T0070 输入**：第 5.7 节将所有支撑第 7 节适用操作的 P0 实施任务定义为 T0069 前置，并逐项明确列出 T0059、T0063、T0064、T0065、T0066、T0067、T0068；规定它们必须先合入并达到“已验收”，候选 SHA 必须包含其合入结果。T0069 要求覆盖第 7 节全部适用验收项并记录候选 SHA、双分区 synth 和 ARN 检查输出。T0070 又被明确约束为只引用该候选提交上的实际输出，不能以其他提交或日期的结果替代。

### 其余计划边界一致性复核

- **任务范围及 P0/P1**：计划第 3 节将 Alpha 聚焦于控制平面、DolphinScheduler、Trino、基础质量和只读 AI 诊断，将 SeaTunnel 全流程、OpenMetadata、Polaris 产品化、FileAsset 实装等留在后续阶段。这与 `ARCHITECTURE.md` 第 2.1 节及 `ROADMAP.md` 的 Alpha/Beta 边界一致。
- **恢复、保留与不适用项**：计划第 5.4、7.1 节为产品 RDS、DS、Keycloak、后台 Catalog、S3 CTAS 数据和实装持久卷定义恢复矩阵；对 OpenMetadata、Polaris 产品化和未实测内存 Catalog 采取不适用或未实施的明确记录，符合架构第 10、11 节“按阶段实施范围验证”的条件。
- **冻结期**：第 5.4 节将功能编码截止设为 11-25，11-26～29 限制为缺陷修复、证据收集和文档。T0067、T0068 在该窗口内是文档和验收准备，不与冻结规则冲突。
- **责任、状态与阻断缺陷**：任务表均提供 Owner/审核、目标日、状态和验收标准；第 5.5 节规定阻断缺陷逐项使用独立 `bugfix/Txxxx-具体缺陷`、回归证据并由 T0070 引用，符合 `ARCHITECTURE.md` 第 13.3 节与 `ROADMAP.md` 的任务流程。
- **分区和实际部署边界**：第 3.1、6、7 项 14 与 7.1 节将真实部署限定为单一 AWS Global Region，将中国区限定为 synth 而非实测。这与 `ARCHITECTURE.md` 第 2.1、3 节和 `ROADMAP.md` 的阶段原则一致。

下列事项需要在对应任务交付、候选提交或真实 AWS 验收时验证，不能从计划、架构和路线图文本判定：

- 第 5.1 节所引历史任务文件中的证据是否真实、完整、可复现，以及审核角色是否已实际完成复核。
- T0069 候选 SHA 是否确实包含所列任务的合入结果，及该候选上的所有测试、Global/CN synth 和 ARN 检查是否通过。
- 第 7 节真实 AWS 部署、两租户隔离、恢复、重复部署、告警、日志脱敏和 AI 降级的实际执行结果。
- T0070 是否会在验收时只引用相同候选基线、相同日期范围内的实际输出。

## 建议

本轮无需修改计划文本。执行阶段应按第 5.7 节的既有规则，在创建 T0069 候选之前逐项确认前置任务已合入且状态为“已验收”，并在 T0070 中保留第 7 节所要求的候选 SHA、命令、时间和输出链接。此建议是对现有计划门禁的执行核对，不新增范围或要求。
